# 数据字典与清洗规则

## 一、三个分析单位

本项目必须区分三个层级，不能混用计数：

| 分析单位 | 唯一键 | 当前用途 |
|---|---|---|
| 更新通知记录 | `Record ID` | 数据覆盖、通知类型和原始原因描述 |
| 撤稿论文 | 规范化 `OriginalPaperDOI` | DOI 级合并、OpenAlex 匹配和建模 |
| 标准化作者 | OpenAlex `author.id` | 作者合作网络节点 |

当前数据有 73,597 条通知记录，但不是 73,597 篇独立撤稿论文。核心窗口 52,638
条 Retraction 记录对应 49,294 个唯一有效 DOI。

## 二、原始字段

完整的机器可读字段说明见 [数据字段字典.csv](数据字段字典.csv)。关键字段如下：

| 字段 | 含义 | 主要用途 | 主要风险 |
|---|---|---|---|
| `Record ID` | 通知记录编号 | 唯一记录审计 | 不能当论文唯一键 |
| `Title` | 通知对应题名 | 匹配抽查 | 缺失、特殊字符和标题变更 |
| `Author` | 作者姓名列表 | 原始合作信息检查 | 无作者 ID，同名严重 |
| `Institution` | 机构自由文本 | 匹配质量核验 | 一字段多机构、缩写和翻译差异 |
| `Country` | 国家列表 | 覆盖描述 | 不能直接视为单一国家 |
| `Publisher` | 出版社名称 | 分层与控制 | 集团、子品牌和更名混杂 |
| `ArticleType` | 文章类型 | 研究类型控制 | 多标签并带尾随分号 |
| `RetractionDate` | 撤稿通知日期 | 时间索引 | 需按美国月/日/年解析 |
| `OriginalPaperDOI` | 原始论文 DOI | 主连接键 | 空白、Unavailable 和格式差异 |
| `RetractionNature` | 通知性质 | 筛选主事件池 | 不同通知类型不能合并 |
| `Reason` | 原因标签列表 | 原因族构造 | 多标签、重叠且非正式裁定 |

## 三、清洗规则

### 3.1 日期

- 原始格式示例：`12/1/2020 0:00`。
- 先删除时:分部分，再按 `%m/%d/%Y` 解析。
- 无法解析记为缺失，不按当前日期补齐。
- 当前数据解析结果为 1756-06-24 至 2026-10-15。
- 1756 年记录来自 Royal Society 历史材料，保留原值；主分析窗口不受影响。

### 3.2 DOI

规范化顺序：

1. 去除首尾空格。
2. 转为小写。
3. 删除 `https://doi.org/`、`http://doi.org/` 或 `doi:` 前缀。
4. 删除末尾的句号、逗号和分号。
5. 把空白、`Unavailable`、`N/A` 和 `NA` 统一为缺失。

当前结果：

- 全库 73,597 条记录中，`doi_canonical` 缺失 5,952 条。
- 核心窗口 52,638 条撤稿记录中，49,453 条有可用 DOI，占 93.95%。
- 核心窗口有 49,294 个唯一有效 DOI。
- 159 条记录属于重复 DOI，分布在 12 个 DOI 组中。

### 3.3 DOI 级折叠

正式论文层按 `doi_canonical` 合并：

- 合并全部 `Record ID` 供审计。
- 对 `Reason` 取并集并去重。
- 撤稿时间取最早有效日期。
- 出版社、期刊和文献类型保留原始值并记录冲突。
- 不得只保留第一条通知后直接删除其他记录。

### 3.4 主事件池

- 主分析仅使用 `RetractionNature == "Retraction"`。
- Expression of concern、Correction 和 Reinstatement 只用于背景和覆盖描述。
- 核心窗口为 2012–2025 年。
- 2026 年只覆盖到冻结日，属于不完整年度，不进入主窗口。

### 3.5 作者数

初步探索按分号拆分原始 `Author` 字段并去重空值。核心窗口结果：

- 中位数 4 人。
- 第 95 百分位 10 人。
- 最大 88 人。
- 无空作者列表。

该结果是姓名层描述，不是 OpenAlex 作者 ID 层结果。正式网络不得直接用这些姓名字符串建边。

## 四、原因族 v1 规则

### 4.1 原则

- 保留全部原始 `Reason`，不覆盖原文。
- 一篇论文可以命中多个原因族。
- 标签表示出版方通知中出现的问题，不是正式学术不端认定。
- 没有明确映射的标签保留为 `unclassified`，不强行归入四类或对照组。

### 4.2 当前映射覆盖

当前有 112 个唯一原因标签，严格 v1 字典只映射 35 个：

| 原因族 | 已映射标签数 | 核心窗口记录数 | 占核心记录 |
|---|---:|---:|---:|
| 数据完整性 | 5 | 2,168 | 4.12% |
| 图像完整性 | 3 | 5,910 | 11.23% |
| 出版流程操纵 | 6 | 24,099 | 45.78% |
| 剽窃与署名 | 9 | 12,266 | 23.30% |
| 严格错误/信息不足对照组 | 12 | 9,069 | 17.23% |
| 未归类 | 77 个标签未映射 | 4,619 | 8.78% |

比例之和超过 100%，原因是多标签重叠。严格对照组定义为“未命中四个原因族，
但命中错误或信息不足标签”。

### 4.3 原因族重叠

核心窗口中：

- 出版流程族与剽窃/署名族同时出现 2,008 条。
- 出版流程族与图像完整性族同时出现 1,139 条。
- 图像完整性族与剽窃/署名族同时出现 1,089 条。
- 数据与图像完整性族同时出现 417 条。

因此模型不能把原因族当成互斥分类。

### 4.4 未归类的主要标签

未归类记录中出现较多的标签包括：

- `Concerns/Issues about Referencing/Attributions`：967 条。
- `Investigation by Journal/Publisher`：794 条。
- `Concerns/Issues about Article`：745 条。
- `Duplication of Content through Error by Journal/Publisher`：632 条。
- `Investigation by Company/Institution`：483 条。

这些标签许多描述调查主体、通知质量或治理过程，并非可直接等同于某一不端原因。
是否扩展映射需要单独确认，并应保留 v1 与扩展版字典的版本对照。

## 五、输出变量

| 变量 | 类型 | 定义 |
|---|---|---|
| `retraction_date` | Date | 解析后的通知日期 |
| `retraction_year` | Integer | 通知年份 |
| `doi_canonical` | Character | 规范化原始论文 DOI |
| `reason_labels` | List | 拆分后的原始原因标签 |
| `n_reason_labels` | Integer | 每条记录的原因标签数 |
| `author_count` | Integer | 原始作者姓名数 |
| `family_data` | Logical | 是否命中数据完整性族 |
| `family_image` | Logical | 是否命中图像完整性族 |
| `family_process` | Logical | 是否命中出版流程族 |
| `family_plagiarism` | Logical | 是否命中剽窃/署名族 |
| `family_control` | Logical | 是否命中严格错误/信息不足对照组 |
| `family_unclassified` | Logical | 是否未命中上述任何族 |

## 六、后续 OpenAlex 字段

正式匹配后至少生成：

- `openalex_work_id`
- `match_status`
- `n_openalex_authors`
- `n_orcid`
- `n_institutions`
- `n_countries`
- `cross_institution`
- `primary_field`
- `publisher_openalex`

匹配状态必须区分 `exact_match`、`not_found`、`invalid_doi` 和 `query_failed`。
查询失败不能算作未找到。

## 七、伦理与解释边界

- 不生成个人撤稿次数或“风险作者”排行榜。
- 不把共同署名解释为共同造假。
- 不把撤稿原因标签解释为法院式或机构式最终裁定。
- 不把撤稿样本占比解释为撤稿率。
- 机构、国家和出版社结论只限于撤稿样本内的结构关联。
