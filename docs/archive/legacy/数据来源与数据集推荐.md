# 数据来源与数据集推荐

## 一、推荐组合

本项目建议采用“一主、一配、一核验”的最小数据组合：

| 优先级 | 数据集 | 在研究中的角色 | 是否可替代 |
|---|---|---|---|
| 主数据 | Retraction Watch Database | 撤稿事实、原因标签、期刊、出版社、原始 DOI | 不可替代 |
| 核心连接数据 | OpenAlex | 作者 ID、ORCID、机构 ID、ROR、国家、学科、来源 | 不可替代 |
| 核验数据 | Crossref REST API | 更新关系、出版社元数据、抽样核验 | 可省略但不能替代主表 |
| 机构校验 | ROR | 机构稳定标识与名称核验 | OpenAlex 已内嵌 ROR，可后置 |
| 可选分母 | OpenAlex 全量作品与来源数量 | 分层描述的总发表规模 | 只有需要分母时使用 |

当前最稳妥的路线是：

```text
Retraction Watch 通知记录
        ↓ 规范化 OriginalPaperDOI
DOI 级撤稿论文表
        ↓ DOI 精确匹配
OpenAlex 作品、作者、机构、学科
        ↓ 辅助抽样
Crossref 更新关系与出版社元数据
```

## 二、为什么以 Retraction Watch 为主

Retraction Watch Database 是唯一同时提供以下信息的核心数据：

- 更新通知性质，可区分 Retraction、Expression of concern、Correction 和 Reinstatement。
- 多条原始原因标签，可直接构造数据、图像、出版流程、剽窃/署名等原因族。
- 原始论文 DOI、期刊、出版社、学科和通知日期。
- 同一论文多条通知记录及对应 Record ID，便于审计。

它不能单独承担作者网络分析。`Author` 是姓名列表，没有稳定作者 ID；`Institution`
也是自由文本。直接按姓名建边会产生同名、拼写变体和迁移机构造成的错误连接。

## 三、为什么以 OpenAlex 为作者与机构主表

OpenAlex 与本研究的需求高度匹配：

- 可通过 DOI 精确取得作品。
- 提供 `authorships[].author.id` 作为作者主键。
- 提供 ORCID、机构 ID、ROR、国家和作者顺序。
- 提供期刊来源、出版社、主题和出版年份。
- 数据为 CC0，适合课程研究、复现和公开代码。

OpenAlex 的 `is_retracted` 只能用于覆盖审计，不能提供 Retraction Watch 的原因标签，
因此不能反过来充当撤稿原因主表。

建议的字段优先级：

1. 作者：`author.id` 为节点主键，ORCID 用于冲突核验。
2. 机构：`institution.id` 和 ROR 为主，原始机构名只用于审计。
3. 学科：优先 `primary_topic` 的领域层级，必要时保留多个 `topics`。
4. 出版社：保留 OpenAlex 来源信息，同时使用 Retraction Watch 标准化出版社名做分层。

## 四、Crossref 的合理用途

Crossref REST API 适合：

- 核对 DOI 是否存在及更新关系类型。
- 抽查撤稿通知、出版社和期刊元数据。
- 比较 OpenAlex 的撤稿标志与 Crossref 更新记录。

Crossref 不适合：

- 提供研究所需的多标签撤稿原因。
- 直接与 Retraction Watch 记录数相减后解释为缺失量。
- 把 `update-type:retraction` 当作完整撤稿数据库。

Crossref、OpenAlex 与 Retraction Watch 的收录逻辑不同。三者只能用于交叉核验，
不能假设记录是一一对应的。

## 五、可选补充数据

### ROR

当 OpenAlex 机构匹配率足够时，ROR 可做机构名称、国家和更名关系的二次校验。
不建议在第一阶段再次全量抓取；OpenAlex 已经返回 ROR。

### OpenAlex 总发表量

若后续需要讨论某个出版社或学科的“撤稿占比”，必须取得对应年份、学科和出版社的
总发表量作为分母。当前只有撤稿样本，因此所有结果只能描述撤稿样本内的结构，
不能解释为撤稿率或学术不端发生率。

### ORCID 公共 API

ORCID 可用于高影响作者节点的人工核验或冲突抽查，但覆盖率不完整，不应作为网络主键。

## 六、不推荐的替代方案

| 方案 | 问题 |
|---|---|
| 只用 Crossref 更新记录 | 没有完整原因标签，通知覆盖与 RWDB 不一致 |
| 只用 OpenAlex `is_retracted` | 只有状态，没有撤稿原因原因族 |
| 直接用 RWDB 作者姓名建网络 | 同名和拼写变体造成实体错误 |
| 使用未标明日期的第三方搬运 CSV | 无法确认版本、字段和完整性 |
| 用撤稿记录数除以 OpenAlex 全部论文数 | 忽略数据库收录、学科和年份差异，不能解释为撤稿率 |

如果后续需要第三方镜像，至少应核对文件哈希、总记录数、字段集合和获取日期；
首轮探索不应把第三方派生表当作原始数据。
