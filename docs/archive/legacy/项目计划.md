# 项目计划

> 状态说明（2026-11-17）：本文件保留最初方案。后续执行以 [研究方向与数据探索方案 v2](研究方向与数据探索方案_v2.md) 和 [ADR 0001](../docs/adr/0001-china-resource-structure-matching-audit.md) 为准。

## 项目名称

**不同撤稿原因如何塑造合作风险网络？——基于 Retraction Watch 与 OpenAlex 的出版治理研究**

## 一、项目目标

在个人独立完成、R 水平较高的前提下，用可复现的数据管道研究不同撤稿原因族对应的作者合作结构、机构分布和时间演化，最终形成一份符合《商务决策分析与 R 语言》课程要求的综合报告、可运行的 Shiny 应用、完整代码与展示材料。

“如何塑造”只表示观察到的结构关联，不表示因果效应。项目不对个人作学术不端事实认定，不提供撤稿作者排行榜。

## 三、研究设计决策

1. 选题采用 C：撤稿关联作者合作网络，并对比原因族结构。
2. 决策对象为出版社或期刊编辑部。
3. 主网络依赖 OpenAlex 标准化作者 ID，不直接用原始姓名。
4. 原因采用四类疑似不端原因族加严格错误/信息不足对照组。
5. 核心分析窗口为 2012–2025 年。
6. 主分析同时覆盖作者、机构、出版社三个层级。
7. 展示默认匿名和聚合，不列个人排行榜。
8. 采用描述统计、网络分析、混合效应回归、时间分析和稳健性检验。
9. Shiny 作为研究型仪表盘，而非报告附件。
10. 数据冻结在 RWDB 2026-10-30 版本，所有下载与匹配结果保留审计记录。

## 四、分析设计

### 4.1 数据准备

1. 下载并校验 RWDB 冻结 CSV，记录 SHA-256。
2. 删除 CSV 末尾空列，按美国日期格式解析日期。
3. 只保留 `RetractionNature = Retraction` 作为主事件池。
4. 保留完整原始记录用于背景趋势，同时构建 DOI 级论文表。
5. 规范化 DOI，按 DOI 合并重复通知，原因取并集。
6. 通过 OpenAlex 每批最多 100 个 DOI 精确匹配作品。
7. 解析作者、ORCID、机构、ROR、国家、学科和期刊。
8. 对匹配率、作者 ID 缺失率和冲突进行分层审计。

### 4.2 原因族构建

- 保留全部 110 个原始标签，不覆盖原文。
- 将标签映射为数据、图像、出版流程、剽窃/署名和严格对照组。
- 多标签编码；报告类别重叠和共现矩阵。
- 主模型不使用单一“主因”强行分类。
- 正式分析前冻结 `reason_dictionary.csv`；如需修订，版本号递增并重跑。

### 4.3 网络构建

#### 作者网络

- 节点：`openalex_author_id`。
- 边：两位作者曾共同出现在同一篇撤稿论文中。
- 同一篇论文内形成团队团；同一作者 ID 在同一论文中去重。
- 主分析使用无权重边，避免超级作者团队重复贡献。
- 敏感性分析使用团队规模归一化权重，降低大团队支配。
- 对“姓名+机构”网络和“作者 ID”网络进行对照。

#### 机构与出版社层

- 机构：聚合作者所属 OpenAlex 机构/ROR。
- 计算机构参与组件数、跨机构桥接、原因多样性和国家分布。
- 出版社：标准化原始名称，不做未经分母控制的“撤稿率”排名。
- 出版社层用于分层统计与控制，不作为责任认定。

### 4.4 网络指标

每个原因族子网络至少报告：

- 节点数、边数、组件数。
- 最大连通组件比例。
- 平均组件规模与组件规模分布。
- 密度与全局聚类系数。
- 度分布偏斜和 Gini 集中度。
- 同机构边比例、跨国边比例。
- 原因族内部边与跨原因族边比例。
- 跨越至少两年的组件比例。
- 社群数、模块度和社群规模分布。

社群检测使用 Leiden；若包版本或加权图支持不足，使用 Louvain 作为稳健性方法。分辨率参数进行扫描，避免只报告一个任意参数下的漂亮社群。

### 4.5 统计推断

#### 论文层混合效应模型

候选结果变量：

- 团队是否跨机构。
- 论文是否属于较大或跨年持续组件。
- 组件规模的分位数或对数变换。

候选解释变量：

- 四个原因族指示变量（多标签）。
- 年份及非线性时间项。
- 学科。
- 作者数。
- ArticleType。
- 出版社随机截距。

主模型形式示例：

```text
outcome ~ data_family + image_family + process_family +
          plagiarism_family + time term + primary_field +
          article_type + n_authors + (1 | publisher_standard)
```

实际模型根据结果变量类型选择混合效应 logistic 或 Poisson/负二项形式。报告固定效应、随机效应方差、置信区间和模型诊断。若收敛失败，使用简化随机效应、正规化先验或固定效应 sensitivity model，并说明原因。

#### 零模型与置换

- 对原因族子网络进行度序列保持的随机重连。
- 比较最大组件、聚类、跨机构边占比和组件跨年持续概率。
- 使用 1,000 次置换形成零分布。
- 多重比较采用 Benjamini-Hochberg FDR 控制。
- 汇报效应量和区间，不只汇报 p 值。

### 4.6 时间分析

- 年度原因族构成。
- 2012–2025 年三年滚动窗口网络指标。
- 分阶段比较：2012–2015、2016–2019、2020–2023、2024–2025。
- 组件年份跨度与重复合作边比例。
- 识别 2023 年论文工厂相关结构变化是否由少数大组件驱动。
- 对 2010–2011 年全库批量事件只做背景和敏感性说明。

### 4.7 稳健性检验

至少完成以下检验：

1. DOIs 匹配子集与未匹配记录的原因族、年份和出版社分布比较。
2. 作者 ID 网络与“姓名+机构”网络的指标对照。
3. 无权重网络与团队规模归一化网络对照。
4. 全 ArticleType 与研究论文子集对照。
5. 多标签编码与“只取明确标签”的窄定义对照。
6. 包含/排除最大五个连通组件。
7. 不带出版社随机效应与带随机效应模型对照。
8. 三年滚动窗口与固定阶段划分对照。

### 运行原则

- 所有原始数据只读。
- OpenAlex 响应按 DOI 批次缓存，失败可重试。
- 随机过程设定固定种子。
- 所有图由脚本生成，不手工改最终数值。
- 数据下载日期、响应版本、行数、哈希和包版本写入 manifest。
- API key、邮箱等只放在环境变量。
- Shiny 启动时读取预计算结果，不在页面打开时重算全网络。

## 六、Shiny 设计

### 页面 1：数据与覆盖

- KPI：总记录、撤稿记录、核心窗口、有效 DOI、匹配率。
- 年度记录量与数据类型构成。
- DOI 匹配率按年份、原因族和出版社分层。
- 数据冻结日期、版本与下载导出。

### 页面 2：原因生态

- 原因族规模与年度趋势。
- 110 个原始标签的搜索表。
- 原因共现热力图。
- 四个原因族与对照组的重叠说明。

### 页面 3：匿名网络探索

- 筛选年份、原因族、出版社、机构国家、ArticleType。
- 展示前若干连通组件或按组件聚合的网络。
- 悬停显示匿名节点 ID、组件、机构数和年份跨度。
- 不提供姓名和“撤稿次数排行榜”。
- 当前筛选的指标卡和边表下载。

### 页面 4：机构与出版社治理

- 机构参与组件数、跨机构桥接、原因族多样性。
- 出版社原因构成与结构指标。
- 小样本自动隐藏或显示不稳定提示。
- 不展示未经总发表量调整的撤稿率。

### 页面 5：时间演化

- 三年滚动最大组件比例。
- 跨国边比例。
- 跨年持续组件比例。
- 关键年份组件拆解与批次事件提示。

### 页面 6：方法与稳健性

- 原因字典版本。
- 模型公式与结果摘要。
- 置换分布、敏感性结果。
- 已知限制与伦理说明。
- 结果与方法下载。

### 交互与性能

- 预计算子网络和摘要指标。
- 单页网络默认不超过约 1,000 个节点，可在说明中明示。
- 采用稳定布局种子，筛选变化时不跳动。
- 所有筛选有明确空状态。
- 移动端保证文字和筛选控件不重叠。
- 提供键盘可用标签与足够色彩对比，不以颜色作为唯一编码。

## 十、主要风险与预案

| 风险 | 预警信号 | 预案 |
|---|---|---|
| OpenAlex 匹配低 | 总体或分层覆盖率低于门槛 | 检查 DOI 规范化；降级作者网络；保留 RWDB 机构层 |
| API 限额或中断 | 429、预算耗尽、超时 | 分批缓存；申请免费 key；次日续抓；不重复请求 |
| 作者 ID 冲突 | 同 ORCID 多 ID、同名异常高频节点 | 标记冲突；人工抽查；机构+姓名网络作为稳健性 |
| 原因族过多重叠 | 四组高度共现，组间差异不可解释 | 报告共现；窄定义敏感性分析；不强行归因 |
| 网络被大组件主导 | 最大组件占比过高 | 报告去掉前五组件结果；按组件聚合；团队规模归一化权重 |
| 模型无法收敛 | 随机效应方差极小或奇异拟合 | 简化模型；固定效应；正规化先验；报告模型选择 |
| Shiny 过慢 | 首屏加载超过 10 秒 | 预计算；只显示前若干组件；分页；关闭自动布局 |
| 结论被伦理质疑 | 读者把网络当“造假者名单” | 匿名节点；聚合展示；明确共同署名不等于共同责任 |
| 时间不足 | 第 6 周模型仍不稳定 | 以网络、描述和稳健性为主，减少次要模型；保持完整闭环 |

## 十一、AI 使用说明方案

课程明确要求说明 AI 工具在哪些环节使用、本人与 AI 如何协作、各自完成什么任务。项目应单独建立 `AI使用说明.md`，至少记录：

| 环节 | AI 可能参与 | 本人必须完成 |
|---|---|---|
| 选题与文献 | 梳理方向、提出研究缺口、辅助检索 | 阅读关键文献并核验引用 |
| 数据源 | 核对字段、下载方式、限制与许可 | 亲自下载数据并检查文件 |
| 代码 | API 请求、清洗、网络和模型草稿 | 逐段理解、运行、调试和测试 |
| 图表 | 提供图形结构和 R 代码草稿 | 核对数据、标签、口径与视觉表达 |
