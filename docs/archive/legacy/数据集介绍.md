# 数据集介绍

## 一、数据方案结论

本项目采用“**Retraction Watch Database 作为撤稿事件与原因标签主表 + OpenAlex 作为标准化作者和机构标识主表 + Crossref REST API 作为更新关系核验与覆盖审计辅助源**”的组合。

Retraction Watch 提供撤稿事实、原因和出版信息，但没有稳定的作者 ID；OpenAlex 提供作者 ID、ORCID、机构 ID、ROR 和学科信息，但它的 `is_retracted` 标志不能替代原因标签。两者通过规范化 DOI 连接，正好互补。

## 二、Retraction Watch Database

- 维护者：Retraction Watch。
- 数据库所有权与公开托管：Crossref 于 2023 年 9 月收购该数据库并公开数据集。

- 数据仓库：https://gitlab.com/crossref/retraction-watch-data

### CSV 结构

字段以逗号分隔；作者、机构、国家、学科和原因等列表字段内部使用分号分隔。

| 字段 | 用途 | 主要问题 |
|---|---|---|
| `Record ID` | RWDB 内部记录编号 | 不能直接当作论文唯一 ID |
| `Title` | 题名核验 | 缺失和特殊字符需处理 |
| `Subject` | 学科背景 | 分类为 RWDB 自有体系，与 OpenAlex 学科不同 |
| `Institution` | 原始机构信息 | 自由文本，一个单元格可含多家机构 |
| `Journal` | 期刊名称 | 名称变体与更名 |
| `Publisher` | 出版社名称 | 并购、沿用旧名、集团与子品牌混杂 |
| `Country` | 作者机构国家 | 列表，不能直接当作单一国家 |
| `Author` | 作者姓名列表 | **没有作者 ID，不能直接用于实体识别** |
| `URLS` | 相关页面 | 可供抽查 |
| `ArticleType` | 内容类型 | 与 Crossref 类型体系不同 |
| `RetractionDate` | 撤稿通知日期 | 格式如 `3/10/2026 0:00`，按美国月份/日期解析 |
| `RetractionDOI` | 撤稿通知 DOI | 不等于原始论文 DOI |
| `OriginalPaperDate` | 原论文日期 | 可用于发表至撤稿的时间差 |
| `OriginalPaperDOI` | 原论文 DOI | 当前主连接键 |
| `RetractionNature` | 更新性质 | 必须筛选 `Retraction` |
| `Reason` | 受控词表原因，多标签 | 标签重叠，需保留原始标签 |
| `Paywalled` | 通知是否付费 | 可用于通知可及性背景分析 |
| `Notes` | 附加说明 | 非结构化，仅用于抽查 |

### 已观察到的数据细节

1. 当前 CSV 每行末尾还有一个空字段，R 的 `readr::read_csv()` 会生成 `...21` 列；应显式删除。
2. DOI 可能为空、`unavailable` 或带 URL 前缀，必须先规范化为小写 DOI。
3. 2012–2025 年存在 159 条重复 DOI 记录。主网络应按规范化 DOI 折叠，合并原因标签并保留最早撤稿年份；记录级描述仍使用原始记录。
4. 年份分布不均匀。2010–2011 年存在明显的批量事件高峰，2026 年是不完整年度，因此核心网络分析采用 2012–2025 年。
5. `Reason` 不是“确认造假”证据，而是出版方通知中出现的问题标签。报告应使用“疑似不端原因标签”，避免把撤稿原因等同于正式学术不端裁决。

## 四、OpenAlex

### 来源与用途

- 官网：https://openalex.org/
- API：https://api.openalex.org/
- 筛选文档：https://help.openalex.org/api/filtering/
- 数据类型：作品、作者、来源、机构、主题等相互连接的研究图谱。
- 许可：OpenAlex 数据为 CC0。
- 本项目用途：由 DOI 获取作品 ID、作者 ID、ORCID、机构 ID、ROR、国家、学科、来源和出版年。

### 关键字段

| 字段 | 用途 |
|---|---|
| `id` | OpenAlex 作品 ID |
| `doi` | 规范化 DOI 连接 |
| `publication_year` | 时间控制 |
| `authorships[].author.id` | 作者网络的主节点 ID |
| `authorships[].author.orcid` | 作者消歧辅助 |
| `authorships[].institutions[].id` | 机构层节点 |
| `authorships[].institutions[].ror` | 稳定机构标识 |
| `authorships[].countries` | 作者机构国家 |
| `primary_location.source` | 期刊与出版社信息 |
| `topics` / `primary_topic` | 学科控制变量 |
| `is_retracted` | 覆盖审计参考，不作为原因来源 |

### 访问方式

DOI 通过 `|` 进行 OR 查询，每次最多可组合 100 个值；单页最多返回 100 条记录。示例：

```text
https://api.openalex.org/works
  ?filter=doi:https://doi.org/DOI_1|https://doi.org/DOI_2
  &per-page=100
  &select=id,doi,publication_year,authorships,primary_location,topics,is_retracted
```

实际 R 脚本应使用 `httr2` 或等价工具进行 URL 编码、分页、重试和速率控制。API 密钥只通过环境变量读取，不写入代码或报告。

### 实际可行性检查

2026-11-01 对核心窗口随机抽取 5 个 DOI，按上述批量方式查询，5 个均返回 OpenAlex 作品记录，且包含作者 ID、机构和国家信息。这只证明接口和字段可用，**不能据此推断全样本匹配率**。正式项目必须计算真实匹配覆盖率。

### 限制

- 作者 ID 仍可能发生错误合并或拆分，ORCID 不是所有作者都有。
- 同一 DOI 的撤稿状态与 RWDB 记录可能不同步。
- 学科分类采用 OpenAlex 体系，与 RWDB 的 `Subject` 不同。
- OpenAlex 的撤稿作品总数与 RWDB 记录数不是同一口径，不能直接相减得出“缺失数量”。
- 免费 API 有预算和速率限制；正式抓取前应建立本地缓存，避免重复请求。

## 五、Crossref REST API

### 用途

- 核对 DOI 是否注册为撤稿更新关系。
- 辅助识别 `update-to`、出版社来源和撤稿通知元数据。
- 对 OpenAlex 的匹配结果进行抽样核查。

### 接口

```text
https://api.crossref.org/v1/works?filter=update-type:retraction&rows=100
```

单作品：

```text
https://api.crossref.org/v1/works/{DOI}
```

Crossref 的更新记录、RWDB 的撤稿记录与 OpenAlex 的 `is_retracted` 标志使用不同覆盖和去重逻辑。三者只用于交叉核验，不能把结果计数直接相减。

## 六、连接与派生数据设计

### 主键与规范化

1. 去除 DOI 的 URL 前缀，转小写并去除首尾空格与尾随标点。
2. 将无法使用的值统一标记为缺失：空白、`unavailable`、`Unavailable`。
3. 对同一 DOI 的多条 RWDB 记录，合并原因标签；保留最早撤稿日期用于时间索引，并保留所有 `Record ID` 供审计。
4. 用规范化 DOI 分 100 个一组请求 OpenAlex，缓存原始 JSON 响应。
5. 仅当 DOI 精确匹配时，将 OpenAlex 作者和机构映射到该论文。
6. 作者 ID 缺失时，不自行用姓名补造 ID；该记录保留在覆盖审计中。
7. 若 ORCID 同时出现在多个 OpenAlex 作者 ID，先标记冲突，人工核验高影响节点。

## 七、覆盖、质量与审计指标

### DOI 匹配

- 核心窗口有效 DOI 数。
- 唯一 DOI 数。
- 成功精确匹配数。
- 未找到、格式无效、查询失败的分项数量。
- 匹配率及按年份、原因族、出版社、ArticleType 分层的匹配率。
- 核查 OpenAlex 返回作品题名与原 RWDB 题名的相似度。
- 人工抽查匹配成功与失败样本各至少 50 条，记录判定标准。

### 作者消歧

- 有 OpenAlex 作者 ID 的作者占参与人次比例。
- 有 ORCID 的作者比例。
- 同一姓名对应多个作者 ID 的数量。
- 同一 ORCID 对应多个作者 ID 的冲突数。
- 高中心性、高重复撤稿次数的匿名节点人工抽查。
- 用“姓名+机构”与纯作者 ID 网络做稳健性比较。

### 建议的可行性分级

| 精确匹配覆盖率 | 处理方式 |
|---|---|
| ≥75% | 可开展主网络分析，并按以上覆盖审计说明局限 |
| 60%–75% | 可开展主分析，但必须报告分层覆盖与潜在选择偏差 |
| 40%–60% | 主结论改为“匹配子集内的探索性结构”，增加原始机构/姓名敏感性分析 |
| <40% | 暂停作者 ID 网络主结论，改为 RWDB 机构层与原因共现分析，并重新评估选题 |

覆盖率门槛是项目管理规则，不是研究结论。

## 八、伦理、许可与发布规范

1. **主展示匿名化。** Shiny 和报告不提供作者撤稿排行榜；网络节点使用匿名 ID。具体 DOI 或记录可在核查模式中检索，但不能将“共同署名”显示为“共同造假”。
2. **聚合优先。** 机构与出版社结果以结构指标和区间展示，避免小样本点名比较。
3. **原始标签可追溯。** 原因族映射不能覆盖原始 `Reason`；附录保留完整映射。
4. **不把撤稿解释为法院式裁决。** 撤稿可能源于诚实错误、出版方失误或作者主动更正。
5. **数据许可。** OpenAlex 数据明确为 CC0。RWDB 在 Crossref GitLab 公开提供，但当前仓库 README 未声明 SPDX 许可证；在进一步确认条款前，不把原始 CSV 直接重新发布到公开仓库，优先分享脚本、聚合结果和派生指标。
6. **API 使用。** 使用环境变量保存 OpenAlex API key；遵守速率限制；缓存响应；不在代码和报告中暴露邮箱或密钥。
7. **引用来源。** 报告和数据说明同时引用 Retraction Watch、Crossref 和 OpenAlex，并写明冻结日期与访问日期。
