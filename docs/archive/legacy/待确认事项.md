# 待确认事项

## 一、需要你确认的两项口径

### 1. 来源版本元数据

当前只有一份完整原始 CSV，包含 73,597 条记录。原项目文档记录的计数为 73,519，
`Retraction` 记录为 68,077；当前文件相应为 68,155。现有材料没有可靠的来源构建
标识，无法判断这些差异来自早期下载不完整、不同构建、筛选口径还是其他原因。

建议：

- **选项 A（当前采用）：以这份 73,597 条文件作为唯一原始数据，记录本地观察日期与哈希。**
- 选项 B：若能取得来源版本说明或官方校验信息，再补充来源版本元数据。

不根据计数差推断文件新旧，也不删除末尾记录来“制造”另一版本。

当前处理：按选项 A 生成全部审计文件和 `manifest.json`，`raw/` 只保留一份原始数据。

### 2. 原因族字典范围

当前严格 v1 字典只映射 35/112 个原始标签，4,619 条核心记录没有命中任何原因族。
未映射标签中有很多是“调查主体”“通知信息不足”或“编辑过程”标签，不一定代表新的原因。

建议：

- **选项 A（推荐）：主分析继续使用严格 v1。**
- 另建扩展 v2，只映射语义明确且可由原文支持的标签，作为敏感性分析。
- 不为了减少未归类比例而批量强制映射。

当前处理：主分析使用严格 v1，并输出 `reason_dictionary_v1.csv` 与未归类标签统计。

## 二、已按项目文档默认执行的事项

以下事项在源文件中已有明确说明，当前直接采用。如无反对，不再中断流程：

1. 主分析单位是规范化 DOI 对应的撤稿论文，不是通知记录。
2. 同一 DOI 的多条通知合并原因并保留最早撤稿日期。
3. 主事件池只保留 `Retraction`。
4. 核心窗口为 2012–2025 年，排除不完整的 2026 年。
5. 原因允许一篇论文命中多个族。
6. 作者网络必须使用 OpenAlex 作者 ID，原始姓名不直接建边。
7. 不出个人作者排行榜，不把共同署名写成共同造假。

## 三、进入 OpenAlex 前需要决定的事项

### 3.1 抓取范围

核心窗口有 49,294 个唯一有效 DOI。可先做 500–1,000 个 DOI 的接口压力测试，
再决定是否全量抓取。

建议：

- 若 API 配额允许，优先全量抓取并缓存原始 JSON。
- 若配额不足，先按出版社和年份分层抽样，不能只做简单随机前 100 条。
- 无论采用哪种方式，都记录请求数、失败数、缓存大小和重试日志。

### 3.2 OpenAlex 覆盖率门槛

项目文档已有门槛：

- ≥75%：可开展主网络分析。
- 60%–75%：报告覆盖偏差后开展主分析。
- 40%–60%：降级为探索性结构分析。
- <40%：暂停作者 ID 网络主结论，转为机构层和原因共现分析。

当前处理：保持该门槛不变。

### 3.3 机构与学科变量

建议主模型使用 OpenAlex `primary_topic` 的更粗领域层级，保留多个主题用于敏感性分析；
机构层优先使用 ROR，无法取得时使用 OpenAlex institution ID。

## 四、当前不影响继续推进的问题

- 出版社原文的完整标准化词典。

- ORCID 冲突的高影响节点人工抽查。

这些问题应在对应分析阶段处理，不需要阻塞本轮数据说明。
