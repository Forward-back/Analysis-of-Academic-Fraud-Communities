# 不同撤稿原因如何塑造合作风险网络？

## 基于 Retraction Watch 与 OpenAlex 的出版治理研究

## 一、选题定位

本项目把学术撤稿记录转化为出版社和期刊编辑部能够使用的治理证据，研究不同撤稿原因是否对应不同的作者合作结构，以及这些结构在机构、出版社和时间维度上如何表现。

这里的“风险”指出版管理中的核查成本和治理风险，不等同于对作者个人学术不端行为的法律或事实认定。共同署名也不意味着共同造假：一篇论文被撤稿，可能只涉及数据来源、图像处理、同行评审或作者责任中的某一环。报告将使用“撤稿关联”“疑似不端原因标签”“合作风险网络”等克制表述。

### 核心问题

不同撤稿原因是否对应不同形态的合作风险网络，出版社能否依据这些结构差异设计更有针对性的初审、同行评审、图像和数据核查流程？

### 核心贡献

1. 从“撤稿数量统计”推进到“撤稿原因与网络结构”的关联分析。
2. 将作者合作、机构聚合和出版社治理放在同一研究框架中。
3. 同时考察原因差异与时间持续性，区分反复出现的结构信号和一次性批量事件。
4. 用标准化作者与机构标识降低同名、拼写差异导致的错误连接。
5. 把结论落到编辑部资源配置和审查流程，而不做个人“造假排行榜”。

## 二、商务情境与决策对象

### 场景

出版社的编辑运营团队需要决定：有限的研究诚信专员、图像检查工具和同行评审复核资源应优先投放到哪些流程和期刊板块。

| 决策环节 | 传统依据 | 本项目可提供的证据 |
|---|---|---|
| 初审分流 | 稿件格式、作者声明 | 哪些原因族更常与跨机构、可重复出现的合作结构相关 |
| 同行评审复核 | 审稿人身份与意见质量 | 论文工厂和评审操纵是否表现出更明显的跨机构、出版社集中结构 |
| 图像与数据核查 | 抽样或编辑经验 | 图像或数据原因族是否更偏向重复作者组、单一机构或长期存续组件 |
| 期刊风险复盘 | 撤稿总量 | 原因构成、集群规模、跨机构程度及时间持续性 |
| 治理资源分配 | 按当期案件排队 | 按原因族的流程痛点和结构信号安排专项能力 |

### 最终管理问题

当出版社面对有限的诚信审查资源时，是否应按撤稿原因配置不同的检查能力，而不是只按撤稿总量或单一“高风险名单”分配资源？

## 三、研究对象与边界

### 分析单位

- 描述统计和覆盖审计：Retraction Watch 的一条更新记录。
- 网络分析：规范化 DOI 对应的一篇撤稿论文，避免同一论文因多条更新记录被重复建边。
- 作者层：OpenAlex 作者 ID，ORCID 仅作辅助核验。
- 机构层：OpenAlex 机构 ID 与 ROR，保留国家代码。
- 出版社层：Retraction Watch 原始出版社名称，经过名称标准化后用于分层和模型控制。

### 原因族

采用多标签编码，一篇论文可以同时属于多个原因族。

| 原因族 | 核心标签示例 | 政策含义 |
|---|---|---|
| 数据完整性问题 | 数据或结果的伪造、篡改、操纵 | 数据来源、原始记录与复现材料核查 |
| 图像完整性问题 | 图像伪造、篡改、操纵、重复使用 | 图像取证与跨论文比对 |
| 出版流程操纵 | 论文工厂、受损同行评审、流氓编辑、计算机生成内容 | 审稿人身份、特刊流程与模板化稿件核查 |
| 剽窃与署名问题 | 文字、数据或图像剽窃，署名或归属争议 | 相似度、作者贡献和机构确认 |
| 错误与信息不足对照组 | 数据/图像/结果错误、不可重复、信息有限 | 区分常规科研失败与疑似不端结构信号 |

对照组定义为“没有命中上述四个原因族，但命中错误、不可重复或信息不足标签”的记录。未映射到任何组的记录保留为“其他/未归类”，不强行塞入对照组。

### 时间窗口

- 全库：用于说明数据库覆盖、长期撤稿变化和异常年份。
- 核心窗口：2012–2025 年，用于网络比较、统计模型和滚动时间分析。
- 排除 2026 年：该年份覆盖至数据冻结日，属于不完整年度。
- 敏感性分析：比较包含或排除 2010–2011 年批量事件的长期趋势。

### 非目标

- 不估计某个国家、机构或作者的真实造假率。
- 不证明共同署名导致造假，也不使用“传播”“传染”等因果措辞。
- 不建立个人高风险排行榜或自动定罪工具。
- 不把撤稿原因标签当作正式调查结论；标签只表示出版方通知中记录的问题。
- 不在没有总发表分母的情况下把撤稿样本份额解释为撤稿率。

## 四、研究缺口与新颖性

现有研究已充分讨论撤稿数据库的建立与原因统计、论文工厂的特征、撤稿引用影响和作者职业后果。代表性工作包括：

- Candal-Pedreira 等（2022）利用撤稿论文分析论文工厂的来源与特征。
- Abalkina（2023）从特定论文工厂案例揭示发表和合作异常。
- Bhattacharyya 等（2025）总结近四十年撤稿的模式和规模。
- Feng 等（2024）分析分子生物学撤稿的引用网络。
- Memon 等（2025）研究撤稿对作者发表生涯的影响。
- Ioannidis 等（2025）连接引用与撤稿数据，研究高被引作者的撤稿人口特征。

这些研究说明撤稿原因、论文工厂和学术影响已有重要基础，但“不同撤稿原因是否对应不同的作者合作结构，并与机构、出版社和时间持续性形成稳定组合”仍缺少直接、系统的课程级实证设计。本项目的相对新颖性不来自声称首次研究撤稿网络，而来自以下组合：

1. 以可审计的多标签原因族作为解释框架，而非只比较撤稿总量。
2. 用标准化作者标识替代姓名直连，并公开匹配覆盖率与误差。
3. 同时观察作者、机构、出版社三个治理层级。
4. 用三年滚动窗口区分持续结构与批次型爆发。
5. 将网络结构与编辑流程建议明确对应。

## 五、分析框架

```text
撤稿通知原因标签
       ↓
四类疑似不端原因族 + 错误/信息不足对照
       ↓
DOI 级论文主体与标准化作者/机构
       ↓
作者合作网络 → 机构聚合 → 出版社治理指标
       ↓
原因族差异 + 时间持续性 + 统计与零模型检验
       ↓
差异化编辑审查流程与资源配置建议
```

### 三个治理层级

1. **作者层**
   - 共同出现在同一篇撤稿论文中的作者形成连接。
   - 使用作者 ID、ORCID、机构和姓名组合核验，不以原始姓名直接建边。
   - 计算连通组件、社群、中心性、重复撤稿作者比例和跨机构边占比。

2. **机构层**
   - 将作者映射到 OpenAlex 机构 ID 与 ROR。
   - 计算机构参与的组件数、原因族多样性、跨机构桥接程度和机构内部封闭程度。
   - 默认只讨论撤稿样本内的结构，不将机构排序解释为机构整体诚信水平。

3. **出版社层**
   - 标准化出版社与期刊名称，控制社内共享流程和编辑政策差异。
   - 比较不同原因族的集群规模、跨机构程度和跨年持续性。
   - 结果用于流程诊断，不将原始撤稿占比直接解释为出版社过失或撤稿率。

## 六、研究假设

假设用于组织分析，不等同于预先认定结论；最终将报告支持、不支持或无定论的证据。

| 编号 | 假设 | 主要检验 |
|---|---|---|
| H1 | 出版流程操纵类记录比数据或图像问题更可能形成较大、跨机构的连通组件 | 原因族网络指标比较、混合效应回归 |
| H2 | 数据与图像完整性问题更可能集中在重复出现的作者组或机构内部，而非巨型组件 | 社群内部连接比例、跨机构边占比 |
| H3 | 不同原因族的时间持续性不同，出版流程操纵更可能呈现阶段性爆发 | 三年滚动窗口、分阶段比较 |
| H4 | 原因族与结构指标的关联在控制年份、学科、作者规模和出版社后仍然存在 | 混合效应 logistic 回归、稳健性检验 |

## 七、预期结果

### 主要结果

1. 全库撤稿趋势、原因构成、DOI 与作者标识覆盖审计。
2. 四类原因族的标签共现热力图与年度趋势。
3. 原因族对应的作者合作网络结构指标。
4. 匿名社群画像：规模、年份跨度、机构数、国家数、原因组合。
5. 机构与出版社治理指标。
6. 三年滚动网络演化图。
7. 混合效应模型与置换/零模型结果。
8. 用于编辑部讨论的差异化审查建议。

### 判断项目是否成功

- 能清楚区分“数据库记录”“撤稿论文”“标准化作者”三个分析单位。
- 能公开报告 RWDB 到 OpenAlex 的匹配覆盖率与匹配误差。
- 四类原因族均有足够样本并给出不稳定性说明。
- 至少两种分析方法相互补充，而非将同一张图换皮。
- 结论在改变窗口、权重和网络指标后仍基本稳定。
- Shiny 能让读者筛选年份、原因族、出版社并查看结构变化。
- 所有核心数字和图表能由冻结数据与 R 脚本重新生成。

## 八、主要风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| DOI 到 OpenAlex 的匹配不完整 | 网络只代表可匹配子集 | 报告匹配率；原始 RWDB 保留全量描述；设置覆盖率门槛与备选方案 |
| 作者消歧错误 | 制造虚假重复作者和错误边 | 以 OpenAlex ID 为主，ORCID/机构/姓名核验；高中心性节点人工抽查 |
| 撤稿原因多标签且含义重叠 | 组间比较不独立 | 使用多标签编码；报告共现；不强制唯一分类 |
| 原因标签不等于正式认定 | 造成过强道德判断 | 统一使用“疑似不端原因标签”；聚合展示；避免个人排行榜 |
| 撤稿规模受出版量与收录偏差影响 | 不能直接比较国家或机构诚信 | 不做无分母的撤稿率推断；结论限定在撤稿样本内的结构关联 |
| 2010–2011 和 2023 等批次事件影响趋势 | 单个事件主导网络 | 核心窗口、三年滚动、事件敏感性分析和组件拆解 |
| 巨型作者团队使网络密度膨胀 | 大团队支配结果 | 主分析使用无权重边；敏感性分析使用团队规模归一化权重 |
| 模型相关不等于因果 | 管理建议越界 | 明确观察性设计；不宣称原因导致网络，不使用“传播”措辞 |

## 十、一句话答辩陈述

本项目不试图给作者“定罪”，而是用标准化合作网络回答一个出版社真正要决策的问题：不同撤稿原因是否需要不同的诚信审查流程。
