# 固定 25 个待核查审计簇

> 状态：首轮候选已固定  
> 主网络：`paper_count >= 2` 的重复合作组件

## 方法

Leiden 在完整网络和重复合作网络上均高度碎片化，因此不作为主候选发现器。
主候选使用重复合作网络的连通组件；Leiden 分区仅作敏感性检查。

候选门槛：

- 至少 5 篇论文含至少两名簇成员。
- 跨至少 2 个撤稿年份。
- 2023 论文占比不超过 50%。
- 排除 2023 后的组件稳定性不低于 0.5。

排序依次使用多年度重复边、内部重复边、论文数、年份跨度和 bootstrap
平均稳定性。最终固定选择 25 个。

## 规模

- 重复合作组件：672。
- 通过最小规模与跨年门槛：45。
- 通过 2023 保护后：38。
- 最终固定审计簇：25。

## 解释边界

- 审计簇表示需要进一步核验的重复合作结构，不是个人或机构责任判断。
- 簇内论文不等于全部由簇成员合作完成；论文纳入条件为至少两名成员出现在同一论文。
- 2023 保护降低了批量事件驱动，但未消除事件影响，仍需在结果中报告批次构成。
- 作者度保持零模型已完成，但两套零模型对应不同估计量，不能使用其差值作因果解释。
- 当前审计簇不能写成因果社群。批次、期刊、原因族、团队规模和地理画像见
  [25 个待核查审计簇画像](audit-cluster-profiles.md)。
